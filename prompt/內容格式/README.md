# Prompt 內容格式：從自然語言到 Markdown 結構化

在 **AI First 的 Vibe Coding（直覺式 AI 編程）** 時代，你與 AI 溝通的指令格式，直接決定了 AI 產出程式碼的架構完整度與介面品質。

許多初學者在進行 Vibe Coding 時，習慣用「自然語言」隨性下指令（例如：「*幫我做一個貪食蛇遊戲，要能玩而且好看*」）。但往往會發現 AI 產出的程式容易缺東漏西——不是漏掉碰撞邊界、缺乏重新開始按鈕，就是介面簡陋、程式碼難以擴充。

學會使用 **Markdown 結構化格式**，就是讓你的 Vibe Coding 從「碰運氣」升級為「精準掌控」的關鍵技巧！

---

## 為什麼 Vibe Coding 特別需要 Markdown 格式？

在請 AI 寫程式時，需求通常涵蓋了**技術選型、遊戲規則、狀態管理、UI/UX 風格與邊界條件**。
- **自然語言**：資訊擠成一整段，AI 的注意力機制（Attention）容易忽視其中的關鍵細節。
- **Markdown 結構化格式**：利用清晰的標題（`#`）、清單（`-`）與粗體（`**`），為 AI 建立一份邏輯嚴密的「產品需求規格書（PRD）」，讓 AI 在生成程式碼時能逐條遵循。

---

## 格式對比示範：以「猜數字小遊戲」為例

我們用同一個小遊戲需求，來看看「自然語言」與「Markdown 結構化」的巨大差異：

### 1. 自然語言（Natural Language）

✏️ **指令寫法**：

> 「請幫我寫一個網頁版的猜數字遊戲，要可以讓玩家猜 1 到 100 之間的數字，如果太大太小要有提示，猜對要顯示恭喜，還要記錄猜了幾次。介面幫我做漂亮一點。」

❌ **常見痛點**：
- **技術棧模糊**：AI 可能隨便選用原生 JS、React 或 Vue，版本難以控制。
- **細節遺漏**：缺乏「輸入驗證（非數字或超出範圍）」、「重新開始」機制。
- **介面憑運氣**：「漂亮一點」過於主觀，AI 產出的樣式通常很陽春。
- **缺乏狀態設計**：沒有規劃遊戲中、遊戲結束的不同畫面狀態。

---

### 2. Markdown 結構化格式（Markdown Format）

✏️ **指令寫法**：

```markdown
# 角色 (Role)
你是一位資深前端工程師與 UI/UX 設計師，擅長建立互動流暢、介面精美的小遊戲。

## 任務目標 (Objective)
請使用 HTML、Vanilla CSS 與 JavaScript（單一檔案或 Vite + React）建立一個現代感十足的「網頁版猜數字遊戲」。

## 核心遊戲規則 (Game Rules)
1. 電腦隨機生成一個 1～100 的整數作為答案。
2. 玩家在輸入框輸入數字後按「猜測」或按 Enter 鍵送出。
3. 判定邏輯：
   - 數字太大：提示「太大了！」，並以冷色系/藍色標示。
   - 數字太小：提示「太小了！」，並以暖色系/橘紅色標示。
   - 猜對：觸發勝利動畫或慶祝特效，顯示「🎉 恭喜猜中！」。
4. 限制與記錄：
   - 玩家最多有 7 次機會，每次猜測即時更新「剩餘次數」。
   - 記錄並列出「已猜過的數字歷史清單」。
   - 次數用盡時遊戲結束，顯示正確答案與「再玩一次」按鈕。

## 介面與視覺風格 (UI/UX & Style)
- **整體風格**：現代科技暗色系（Dark Mode），搭配細緻的毛玻璃效果（Glassmorphism）與微漸層。
- **排版佈局**：置中卡片式設計，支援響應式（RWD，手機與桌機皆適配）。
- **互動反饋**：按鈕懸停（Hover）特效、輸入錯誤提示抖動效果。

## 輸出要求 (Output Format)
- 程式碼結構清晰，邏輯層與畫面渲染分明。
- 關鍵邏輯需加上繁體中文註解。
- 提供完整且可直接運行的程式碼。
```

✅ **結構化優勢**：
- **邊界條件完整**：7次限制、防呆輸入、歷史清單全部列出。
- **風格明確**：指定 Dark Mode 與毛玻璃，AI 不會交出預設白色陽春介面。
- **高再現性**：任何時候把這份 Prompt 貼給 AI，產出結果都能維持極高水準。

---

## 兩者比較表

| 比較維度 | 自然語言（口語式） | Markdown 結構化格式 |
| :--- | :--- | :--- |
| **輸入方式** | 一段式純文字，想到什麼寫什麼 | 分層標題、條列要點、結構化區塊 |
| **資訊層次** | 扁平無層級，細節容易被忽略 | 階層分明，角色、邏輯、UI 各自獨立 |
| **Vibe Coding 成功率** | 較低，需反覆對話 3~5 次修正漏掉的功能 | 極高，往往能一次到位（One-shot 完成） |
| **維護與擴充** | 修改某個條件時容易造成語意混亂 | 模組化，可隨時抽換或擴充特定規則 |
| **適用時機** | 隨想討論、靈感發想、快速測試語意 | 建立完整小專案、功能元件、上架級應用 |

---

## Vibe Coding 的 Markdown 黃金架構（RTCCF）

在寫程式類 Prompt 時，掌握以下五大區塊，就能組裝出專業的 Prompt：

```markdown
# 1. 角色 (Role)          -> 例如：資深前端工程師、React 專家
## 2. 任務目標 (Task)      -> 明確指出要打造的專案或元件
## 3. 背景情境 (Context)   -> 專案架構（Vite / React / TypeScript）、執行環境
## 4. 具體限制 (Constraint)-> 遊戲規則、生命次數、不能使用的套件、邊界條件
## 5. 輸出規格 (Format)    -> UI/UX 風格要求、檔案組織方式、繁體中文註解
```

### 1. [猜數字遊戲](../../AIFirst實作課程/建立小遊戲/猜數字遊戲/README.md)
> 🎮 **遊戲簡介**：電腦隨機產生一個數字，玩家需要透過提示（太大、太小）來猜出正確的數字。

- **練習目標**：撰寫一份結構化 Prompt，要求 AI 實作「難度選擇（1-50 / 1-100）」、「次數倒數」、「歷史猜測記錄」與「動態數字範圍縮小顯示」。

<details>
<summary>💡 點擊展開：參考 Prompt 範本</summary>

<br>

```markdown
# 角色
你是一位資深網頁前端工程師，專精於現代 UI/UX 設計與邏輯遊戲開發。

## 任務
請使用 HTML、CSS 與 JavaScript 建立一個具有現代視覺美感的「猜數字益智遊戲」。

## 遊戲規格與規則
1. **數字生成**：遊戲開始時隨機生成 1～100 的秘密整數。
2. **難度與限制**：玩家共有 7 次機會，畫面上需有明顯的剩餘次數倒數指示器。
3. **判定提示**：
   - 猜太大：提示「數字太大了！」，顯示向下的箭頭。
   - 猜太小：提示「數字太小了！」，顯示向上的箭頭。
   - 猜中：顯示勝利慶祝動畫，並公佈總共猜了幾次。
   - 次數耗盡：顯示「挑戰失敗」，並揭曉正確答案。
4. **範圍縮小輔助**：畫面上即時顯示目前可能的數字區間（例如：從 `1 ~ 100` 縮小為 `35 ~ 68`）。
5. **重開機制**：隨時提供「重新開始」按鈕，重置遊戲狀態。

## 介面與樣式要求
- 採用乾淨、俐落的卡片式介面與舒適的漸層背景配色。
- 具備友善的輸入驗證（不能輸入小於 1 或大於 100，或非數字字元）。
- 支援手機觸控與電腦鍵盤 Enter 鍵提交。

## 輸出格式
- 請提供完整、無省略的單一 HTML 檔案（內含 CSS 與 JS），方便直接預覽執行。
- 程式碼需有清晰的中文註解。
```

### 2. [貪食蛇遊戲](../../AIFirst實作課程/建立小遊戲/貪食蛇遊戲/README.md)
> 🎮 **遊戲簡介**：經典街機遊戲。玩家控制一條蛇移動吃食物來成長，但要避免撞到牆壁或自己的身體。

- **練習目標**：撰寫一份結構化 Prompt，要求 AI 使用 HTML5 Canvas 或 CSS Grid 實作蛇身移動、鍵盤方向鍵控制、食物生成與碰撞判定。

<details>
<summary>💡 點擊展開：參考 Prompt 範本</summary>

<br>

```markdown
# 角色
你是一位熟練 HTML5 Canvas 遊戲開發的前端工程師。

## 任務
請使用 HTML5 Canvas、CSS 與 JavaScript 打造經典的「網頁版貪食蛇小遊戲」。

## 核心遊戲機制
1. **畫布與移動**：
   - 遊戲區域為 400x400 像素的網格地圖。
   - 蛇初始長度為 3 節，以穩定的速度向前移動。
   - 支援鍵盤方向鍵（↑ ↓ ← →）與 WASD 鍵控制轉向，且防止 180 度直接反向自撞。
2. **食物與成長**：
   - 地圖上隨機位置生成食物（不能生成在蛇身上）。
   - 吃到食物後：蛇身加長一節、計分 +10 分、並隨機生成新食物。
3. **死亡與結算條件**：
   - 撞到畫布邊界牆壁。
   - 蛇頭撞到自己的身體。
   - 死亡時停止遊戲迴圈，彈出結算面板顯示本局分數與歷史最高分。
4. **輔助功能**：提供暫停功能（按空白鍵或 P 鍵）與「再玩一局」按鈕。

## UI 與視覺風格
- 復古像素風（Retro Arcade）或現代霓虹螢光暗色風（Neon Glow）。
- 頂部狀態列清晰展示「當前得分」、「歷史最高分」與「遊戲狀態」。

## 輸出格式
- 請提供單一可直接運行的 HTML 檔案，包含完整 Canvas 繪圖邏輯與流暢的遊戲迴圈（使用 requestAnimationFrame）。
```

### 3. [反應力測試](../../AIFirst實作課程/建立小遊戲/反應力測試/README.md)
> 🎮 **遊戲簡介**：測試玩家反應速度的遊戲。玩家需要在看到特定訊號時快速做出反應（點擊或按鍵）。

- **練習目標**：撰寫一份結構化 Prompt，要求 AI 實作「狀態機（State Machine）」架構（等待中、準備中、點擊、結算），並精準計算毫秒反應時間與防作弊機制。

<details>
<summary>💡 點擊展開：參考 Prompt 範本</summary>

<br>

```markdown
# 角色
你是一位專注於使用者互動與狀態管理的資深 Web 開發者。

## 任務
請使用 HTML、CSS 與 JavaScript 建立一個精準的「人體反應力測試（Human Benchmark Reaction Time）」小遊戲。

## 狀態機與流程規則
遊戲必須明確區分以下四種狀態，並用全螢幕大色塊切換呈現：
1. **閒置狀態 (Idle / 藍色)**：
   - 畫面顯示標題、玩法說明與「點擊任意處開始測試」按鈕。
2. **等待狀態 (Waiting / 紅色)**：
   - 畫面轉為紅色，文字提示「請稍候，等綠色出現再點擊...」。
   - 系統啟動 1.5 ～ 5 秒的隨機延遲計時器。
   - **防作弊判定**：若玩家在此階段提早點擊，立即切換為警告畫面（黃色/太早按了！），要求重新再來。
3. **反應狀態 (Ready / 綠色)**：
   - 隨機等待結束，畫面瞬間轉為亮綠色，文字提示「現在立即點擊！」。
   - 系統記錄當下時間戳記（使用 `performance.now()` 保證高精度）。
4. **結果結算 (Result / 紫色或暗色)**：
   - 玩家點擊後計算毫秒數差值（Reaction Time in ms）。
   - 顯示成績，並給予評級（例如：< 200ms 神人等級、200~300ms 正常、> 300ms 稍慢）。
   - 記錄最近 5 次的成績並計算平均反應時間。

## 輸出格式
- 程式碼結構清晰，狀態轉換邏輯需嚴謹封裝。
- 包含完整 HTML、CSS、JS 程式碼，確保行動裝置觸控與電腦滑鼠點擊皆能零延遲觸發。
```

### 4. [打磚塊遊戲](../../AIFirst實作課程/建立小遊戲/打磚塊遊戲/README.md)
> 🎮 **遊戲簡介**：經典街機遊戲。玩家控制一個平台（paddle）來反彈球，擊破上方的磚塊。目標是清除所有磚塊。

- **練習目標**：撰寫一份結構化 Prompt，要求 AI 實作「滑塊移動控制、球體物理反彈、磚塊碰撞消除、生命次數與通關機制」。

<details>
<summary>💡 點擊展開：參考 Prompt 範本</summary>

<br>

```markdown
# 角色
你是一位遊戲開發與 2D 物理碰撞算法專家。

## 任務
請使用 HTML5 Canvas 與原生 JavaScript 開發一個流暢好玩的「經典打磚塊（Breakout）遊戲」。

## 核心物理與遊戲規則
1. **控制滑塊（Paddle）**：
   - 位於畫布底端，支援滑鼠左右移動跟隨，或鍵盤左右鍵（← →）平滑操控。
2. **彈球（Ball）與碰撞反彈**：
   - 球體在畫布內運動，碰到左、右、頂部邊界時進行角度反射。
   - 碰到滑塊時反彈，且反彈角度隨撞擊滑塊的位置不同而改變（撞邊緣角度更大）。
3. **磚塊陣列（Bricks）**：
   - 頂部排列 4 行 x 8 列的彩色磚塊。
   - 球體擊中磚塊時，該磚塊消除、得分增加、球體反彈。
4. **生命與勝負判定**：
   - 球掉落底端未被滑塊接住時，扣除 1 點生命值（共 3 點生命）。
   - 生命值歸零時「遊戲結束（Game Over）」。
   - 清除所有磚塊時「恭喜通關（You Win!）」。

## 視覺與音效體驗
- 現代街機風格，磚塊依行數有不同色彩層次。
- 頂部 HUD 顯示「得分」與「剩餘生命（愛心圖示）」。

## 輸出格式
- 提供單一 HTML 檔案，包含完整 Canvas 碰撞檢測演算法（AABB 碰撞判定）。
- 邏輯迴圈順暢，無畫面卡頓或穿透磚塊的 Bug。
```

</details>
